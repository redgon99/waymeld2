# 「랜딩~동선짜기 디자인 리뉴얼」작업지시서

> 용도: 클로드 디자인(Claude Design)에 의뢰할 랜딩페이지~플래너(동선짜기) 리디자인 브리프
> 작성일: 2026-08-31
> 배경: 랜딩페이지 배너에 "8월 한 달간 시범 운영하며, 9월부터 정식 운영합니다"라고 명시돼 있음 — 정식 운영 전환 시점에 맞춘 리뉴얼

---

## 0. 한 줄 요약

**"방문 지도가 아니라, 오늘 갈 동선"**이라는 제품의 핵심 가치를, 랜딩페이지를 본 첫 10초 안에 그리고 플래너에 처음 들어온 첫 조작 안에 사용자가 스스로 느끼게 만드는 것이 이번 리뉴얼의 목표입니다. 기능은 이미 다 있습니다 — 지금 문제는 **그 기능들이 어디 있는지 찾기 어렵고, 일부 화면은 실제로 깨져 있다**는 것입니다.

---

## 1. 제품이 무엇인지 (디자이너가 알아야 할 최소 맥락)

- **이름**: WayMeld(여로담) — 한국 여행 전용 동선(코스) 플래너. 예약·결제 앱이 아님.
- **핵심 루프**: 검색 → 핀업(카테고리별 자동 정리) → 드래그로 순서 조정 → 몇 시에 어디 갈지까지 나오는 시간표 동선 → 공유.
- **한 줄 포지션**(기존 카피, 유지할 것): "방문 지도가 아니라, 오늘 갈 동선."
- **차별점**: Pin Traveler류의 "방문 지도·기록" 앱과 다르게 **다음에 갈 곳을 짜는 도구**. Wayby(경쟁 동선 앱, 이미 앱스토어 구독 서비스 운영 중)나 마이리얼트립(OTA)과도 다르게 **예약을 팔지 않고 코스 짜기에만 집중**.
- **사용자 두 축**: ① 국내 여행을 반복적으로 계획하는 한국 로컬 사용자 ② 한국 여행을 준비하는 외국인(9개 로케일 지원 — de/en/es/fr/ja/ko/ru/zh-CN/zh-TW).
- **수익모델**: Free(여행 3개·기본 검색) → Plus 월 구독(무제한 저장·클라우드 동기화·다국어 export·실경로 동선). 구독 결제 파이프라인은 최근 신규 구축됨.

## 2. 지금 화면의 실제 문제 (모바일 실기기 뷰포트 점검 기준, 2026-08-30 확인)

리디자인 근거가 "느낌"이 아니라 **실제로 확인된 문제**라는 걸 명확히 하기 위해, 이번 주 직접 모바일(390px 폭) 뷰포트로 점검하며 찾은 것들을 그대로 남깁니다.

| 화면 | 문제 | 심각도 |
|---|---|---|
| 랜딩페이지 헤더 | "클라우드 저장(로그인)" 버튼 안의 텍스트가 좁은 화면에서 **한 글자씩 세로로 줄바꿈**되어 읽을 수 없는 상태로 깨짐 | 높음 — 첫인상에서 바로 보임 |
| 업그레이드(Plus 구독) 모달 | 배경 딤 처리·카드 중앙정렬 스타일이 아예 누락되어 있어 열리면 화면이 흐트러질 가능성이 높음(코드 검사로 확인, 최초 커밋부터 있던 문제) | 높음 — 결제 전환의 첫 접점 |
| 플래너 진입("새 여행" 만들기, 계정/플랜 상태 확인) | 데스크톱 상단바(`PlannerAppBar`)는 모바일에서 아예 숨겨지고, 모바일에서 이 기능들에 대응하는 진입점이 여러 단계 메뉴 뒤에 흩어져 있어 **직접 조작으로 찾는 데 여러 차례 시도가 필요했음** | 중간 — 신규 사용자 온보딩 이탈 위험 |
| 플래너 하단 시트 | "핀 0 / 동선" 탭, "⋯" 더보기 메뉴(공유·테마 여행 만들기·한국 준비·도움말), 카테고리 칩, 검색창, 일차 탭 등 **기능 밀도가 매우 높고 위계가 평평함** — 뭐가 우선인지 구분이 잘 안 됨 | 중간 |

**리뉴얼 시 반드시 손볼 것**: 위 표의 두 "높음" 항목은 최소한 구조적으로 재설계되어야 하고(임시 CSS 땜질이 아니라), "새 여행 시작하기"는 모바일에서 화면 진입 즉시 눈에 띄어야 합니다.

## 3. 디자인 목표 (우선순위 순)

1. **첫 화면에서 "핀업→동선" 핵심 루프가 3초 안에 이해되게.** 지금 랜딩은 카피는 좋은데(§4 참고) 실제 플래너 화면의 미리보기/데모가 약합니다. "이 화면이 무엇을 해주는 도구인지"를 스크린샷/모션이 아니라 실제로 조작 가능한 느낌으로 보여줄 것.
2. **모바일 우선.** 실사용자 비중이 모바일에 쏠릴 가능성이 높은 제품(여행 중 즉석 확인)인데, 지금 데스크톱 상단바가 모바일에서 통째로 사라지고 그 기능들이 재배치가 아니라 "숨김"에 가깝게 처리돼 있습니다. 모바일 내비게이션을 별도 설계할 것 — 데스크톱 UI를 축소하는 방식이 아니라.
3. **정보 위계를 세운다.** 지금 하단 시트/더보기 메뉴에 기능이 평면적으로 나열돼 있습니다(핀·동선·공유·테마여행·한국준비·도움말·자료·검색 필터 등). "지금 이 순간 사용자가 할 가능성이 가장 높은 행동"이 항상 엄지 닿는 자리에 있고, 나머지는 접혀 있어야 합니다.
4. **Plus 업그레이드 접점을 신뢰감 있게.** 지금은 모달 스타일이 깨져 있을 뿐 아니라, 애초에 언제 이 모달이 뜨는지도(여행 3개 제한, 검색 한도 등) 사용자가 예측하기 어렵습니다. "왜 지금 이게 떴는지 · 뭘 얻는지 · 어떻게 되돌릴 수 있는지"가 한 화면에서 바로 읽혀야 합니다.
5. **기존 브랜드 톤은 유지·강화.** 남색+옐로 조합, 카드형 pill 버튼, 손글씨 느낌 아닌 굵은 산세리프 헤드라인 — 이 톤 자체는 나쁘지 않습니다(§4). "다시 그리기"가 아니라 "정리하고 위계를 세우기"에 가깝게 접근할 것.

## 5. 작업 범위

### 포함
1. **랜딩페이지** (`/`) — 히어로, 3 pillars(검색&핀업/동선 만들기/공유&템플릿), 경쟁 비교 섹션, 사용법(how-it-works), 갤러리, 하단 CTA band. 전체 재구성 가능.
2. **플래너 진입/온보딩** — 첫 방문 시 "무엇을 해야 하는지" 안내(현재 `OnboardingCoach` 3단계 코치마크), 신규 여행 만들기 진입점.
3. **동선짜기 코어 화면**(`/plan`) — 지도, 검색, 핀 목록, 카테고리 필터, 일차 탭, 동선(시간표) 보기, 하단/사이드 패널. **모바일 레이아웃을 데스크톱의 축소판이 아니라 별도로 설계.**
4. **Plus 업그레이드 모달** — 트리거 시점(여행 개수 제한, 검색 한도 등)에 맞는 문구·비주얼, 업그레이드/해지 상태별 화면.
5. **모바일 내비게이션 구조 자체** — 지금 흩어진 더보기 메뉴들(핀시트 더보기, 상단 ⋯ 메뉴)을 정리해 하나의 일관된 체계로.

### 제외 (이번 스코프 아님)
- 결제 플로우 내부 로직, 이용약관/개인정보처리방침 페이지 — 최근 신설된 그대로 유지(내용 검수는 별건).
- 관리자 페이지(`/admin/*`).
- 공유마당(`/plaza`), 가이드(`/guides`) — 필요 시 후속 라운드.

## 6. 핵심 사용자 플로우 (반드시 보존)

디자인이 바뀌어도 아래 흐름의 **단계 수·조작 방식**이 지금보다 나빠지면 안 됩니다.

1. 목적지 검색 → 카테고리별 결과 → 핀업(지도/목록 양쪽에서 가능)
2. 여러 날짜(일차) 탭 전환, 각 일차별 핀 목록 관리
3. 핀 순서 드래그 재배치 → "동선" 탭에서 시간표(도착/출발 시각, 체류시간, 이동시간) 확인
4. 카카오맵 ↔ 구글맵 프로바이더 전환(국내/해외 자동 판정 — 현재는 좌표 기반)
5. 공유 링크 생성 / 여행 자료(사진·메모) 첨부
6. Free 한도 도달 → Plus 안내 → 결제 → 해지

## 7. 제약사항

- **지도 SDK 영역(카카오/구글 지도 캔버스) 자체의 인터랙션은 각 지도사 SDK에 종속**되어 자유 디자인이 불가능합니다 — 그 위에 얹는 UI(검색바, 핀 마커 스타일, 오버레이 카드)만 대상.
- 9개 로케일을 지원하므로 **텍스트 길이 편차가 큰 언어(독일어 등)를 고려한 여유 있는 버튼/라벨 폭**으로 설계할 것 — 이번에 발견된 "텍스트 줄바꿈 깨짐" 버그가 다국어 환경에서 반복되지 않게.
- 1인 개발자 + AI 코딩보조 체제로 구현되므로, **복잡한 커스텀 애니메이션·특수 인터랙션보다 표준 컴포넌트 조합으로 구현 가능한 디자인**을 우선할 것(구현 리스크 최소화).
- 기존 컬러 토큰(§4)과 pill 버튼 형태는 브랜드 자산이므로 유지.

## 8. 산출물 형식

- 데스크톱 + 모바일(390px 기준) **두 사이즈** 목업을 화면별로.
- §5 "포함" 범위의 화면들을 하나의 pan/zoom 캔버스에 아트보드로 배치.
- 최소 두 가지 대안(특히 랜딩 히어로와 모바일 플래너 내비게이션)을 비교 검토할 수 있게.
- 문제점(§2)에 대해 각각 "이 목업에서 어떻게 해결했는지" 짧은 캡션 부기.
