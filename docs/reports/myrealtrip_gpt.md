\## 마이리얼트립의 빈틈



현재 공개된 웹·앱의 중심은 여전히 상품 검색과 예약입니다. Waymeld와 같은 다음 기능은 전면에 드러나지 않습니다.



\* 여러 장소를 한 지도에 모으기

\* N일차별 자유로운 장소 배치

\* 장소 간 실제 이동시간 자동 계산

\* 방문 순서 자동 최적화

\* 식사시간·피로도·동행자 조건 반영

\* 자유 장소와 예약 상품을 섞은 하루 일정 자동 재계산



마이리얼트립도 이 문제를 정확히 알고 있습니다. 2025년 ‘Oh My Planner’ 실험에서는 일정 데이터가 거의 없었고, 전체 상품 중 코스 데이터가 있는 비율이 19%에 불과했다고 밝혔습니다. \[AI 일정 실험](https://blog.myrealtrip.com/ai-itinerary-experiment/)



하지만 2026년에는 MCP를 이용해 날짜·동행자·상품 재고를 반영한 대화형 여행 설계를 실험했고, “AI 추천을 실제 예약 가능한 일정으로 좁히는 문제”를 공개적으로 추진하고 있습니다. \[대화형 여행 설계 PoC](https://blog.myrealtrip.com/ai-travel-conversation-search/), \[AI 추천과 예약 연결](https://blog.myrealtrip.com/ai-cuceongwa-yeyag-saiyi-georireul-jobhineun-beob-mairieolteuribi-jokoding-ax-haekeotone-naen-munje/)



따라서 현재는 Waymeld가 플래너 기능에서 앞서지만, 이 격차가 영구적이라고 보기는 어렵습니다.



\## Waymeld가 확실히 우위인 부분



현재 `redgon99/waymeld`의 `main` 코드를 기준으로 보면 다음은 이미 상당히 경쟁력이 있습니다.



\* 카카오 모빌리티 실도로 이동시간

\* 자동 순서 최적화와 사용자 순서 고정

\* 체류시간·점심시간·피로도 반영

\* 다일차 일정과 타임라인

\* TourAPI 4.0, 고캠핑, 무장애·반려동물, 두루누비, Odii

\* YouTube·웹 링크에서 장소 추출

\* 카카오·Google 이중 지도

\* 한국어·영어·일본어·중국어

\* 택시기사용 한국어 카드와 음식 제약 정보

\* 공유마당, 공유 링크, CSV·KML·GPX 내보내기



반대로 현재 가장 큰 약점은 기능 부족보다 다음 네 가지입니다.



1\. \*\*유입 부족\*\*

&#x20;  SPA 폴백, 고정 메타, 사이트맵·페이지별 OG 부재로 검색 유입이 약합니다.



2\. \*\*검증 가능한 상업 데이터 부족\*\*

&#x20;  장소는 많지만 실제 가격·재고·예약 가능 여부가 없습니다.



3\. \*\*신뢰 데이터 부족\*\*

&#x20;  자체 후기·예약 실적·판매자 검증·고객지원이 없습니다.



4\. \*\*수익화 미완성\*\*

&#x20;  Free·Plus·Team 제한 코드는 있지만 실제 결제·웹훅은 아직 연결되지 않았습니다.



\## 가장 적합한 마이리얼트립 연동 방식



Waymeld 안에 작은 OTA를 만들면 안 됩니다. 결제·취소·바우처·판매자 관리까지 직접 맡는 순간 개발과 운영 범위가 폭발합니다.



대신 다음처럼 일정 객체를 분리하는 것이 좋습니다.



| 일정 객체  | 데이터 출처             | Waymeld 처리      |

| ------ | ------------------ | --------------- |

| 자유 장소  | TourAPI·카카오·Google | 자유롭게 순서 최적화     |

| 예약형 체험 | 마이리얼트립 투어·티켓 API   | 시작시간·소요시간을 고정   |

| 숙소     | 마이리얼트립 숙소 API      | 하루의 출발·종료 앵커    |

| 항공     | 마이리얼트립 항공 API      | 전체 여행의 시작·종료 경계 |



첫 연동은 \*\*투어·티켓·액티비티만\*\* 하는 것이 가장 적절합니다.



예를 들어 사용자가 오사카 일정을 만들면:



1\. 현재 동선 주변의 예약 가능 체험 검색

2\. 가격·평점·소요시간·취소조건 표시

3\. 일정에 추가하면 고정시간 일정으로 전환

4\. 앞뒤 장소를 Waymeld가 다시 최적화

5\. 시간 충돌이나 이동 불가능 여부 경고

6\. 결제는 마이리얼트립으로 이동

7\. Waymeld는 추천·클릭·전환 수익만 추적



운영 환경에서는 REST Open API를 Supabase Edge Function 뒤에서 호출하고, MCP는 프로토타입과 AI 추천 실험에 사용하는 구성이 안전합니다. 마이리얼트립은 사이트 콘텐츠의 무단 스크래핑을 명시적으로 금지하므로 반드시 공식 API만 사용해야 합니다. \[이용 안내가 포함된 공식 홈페이지](https://www.myrealtrip.com/)



\## 최종 우선순위



1\. \*\*마이리얼트립 마케팅파트너 가입 및 API 키 발급\*\*

2\. 투어·티켓 검색 결과를 Waymeld 일정 주변에 최대 3개만 노출

3\. 상품을 `고정시간 일정`으로 넣고 전체 동선 재계산

4\. 가격·재고 확인 시각과 예약 가능 상태 표시

5\. 노출→클릭→일정 추가→예약 이동 전환 분석

6\. 성과가 확인된 뒤 숙소 앵커 추가

7\. 항공 검색은 가장 나중에 검토



핵심 포지셔닝은 그대로 유지하는 것이 좋습니다.



> \*\*마이리얼트립은 예약을 완성하고, Waymeld는 여행이 실제로 가능한 동선인지 완성한다.\*\*



즉, Waymeld는 마이리얼트립을 이기려 하기보다 \*\*여러 예약 서비스 위에서 동작하는 독립적인 여행 실행 엔진\*\*이 되어야 합니다.
